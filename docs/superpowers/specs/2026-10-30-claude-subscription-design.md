# Claude サブスク経由の字幕翻訳・解説

状態: 2026-10-30 に実装・PR 作成を承認済み。

## 目的と確認済みのこと

Useful Subtitle の AI 翻訳・解説を、別払いの Anthropic API ではなく、Claude Pro の月額契約の利用枠で使う。

Claude Code がインストールされ、利用する Pro 契約のアカウントでログイン済みであることを前提とする。CLI の認証方式を確認し、表示されるプラン名だけから契約内容を断定しない。認証情報のファイルや `.env` を直接読む必要はない。

Anthropic の 2026-10-07 更新の公式案内では、Claude のプランでログインした `claude -p` は現在も契約の利用枠を消費する。API キーを使う場合とは別の経路である。

- https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan
- https://code.claude.com/docs/en/headless
- https://support.claude.com/en/articles/12304248-manage-api-key-environment-variables-in-claude-code
- https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan

## 提案する利用体験

設定画面に「Claude サブスク（この Mac の Claude Code）」を追加する。既存の API 設定は保持し、ユーザーがサブスク方式を選択した後は API キーを使わない。今の字幕取得、単語辞書、発音音声、履歴、Prime Video / YouTube 対応は維持する。

対象は自動の日本語訳、語句の解説、履歴の一文解説、接続テスト。モデルは既存の Haiku 5.5 を優先する。サブスクで使えない場合はエラーを表示し、別モデル・API へ無断で切り替えない。

初回だけ、拡張機能と Mac の接続用プログラムを登録する。設定画面に拡張機能 ID と、その ID を指定したセットアップコマンドを表示する。登録後は普段どおり動画を開いて使え、ターミナルや開発サーバーを起動しておく必要はない。

API 直結より待ち時間が増える可能性がある。動画本来の字幕は即時に表示し続け、AI の和訳・解説は応答後に表示する。全行のリアルタイム和訳は保証しない。処理が追いつかないときは古い自動和訳の待ち行列を捨て、最新の字幕とユーザーが要求した解説を優先する。この点は設定画面にも短く明記する。

## 構成（設計者の提案）

拡張機能 → Native Messaging の接続用プログラム → `claude -p` → Claude。

Chrome 系ブラウザの Native Messaging を利用する。外部公開ポート、localhost HTTP サーバー、常時起動するサービスは追加しない。Mac / Brave を最初の動作確認対象とする。

- 拡張に `nativeMessaging` 権限を追加し、background で接続を管理する。
- 接続用プログラムは Node.js で作り、標準入出力の JSON メッセージを処理する。
- 接続中のみプロセスを保持する。依頼がない状態で一定時間経過したら切断・終了する。
- Claude はリクエストごとに起動し、同時実行を 1 件に制限する。呼び出し終了時にプロセスを回収する。重複要求はまとめ、待機件数にも上限を設ける。
- 自動和訳はタブごとに最新の未処理要求だけを残す。語句・一文解説と接続テストを優先する。処理中の古い和訳の結果は現在の字幕へ上書きしない。
- 切断、タイムアウト、ログイン切れ、モデル未対応、利用上限、セットアップ未完了をユーザーに説明する。大量の自動再試行はしない。
- キャッシュを方式・モデル・言語ごとに分離する。

Native Messaging の根拠: https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging

## 課金・認証・入力の境界

サブスク方式から有料 API への自動フォールバックは禁止する。API キーを設定していても、サブスク呼び出しには渡さない。子プロセスの環境は必要な値だけを許可し、API キー、外部プロバイダ設定、独自 API エンドポイントなどを引き継がない。ログインは公式 CLI に任せ、OAuth トークンを読み出したり拡張へ保存したりしない。

起動前の認証チェックで Claude プランによる認証を確認する。`--bare` は OAuth を読まないため使用しない。利用中の CLI が提供する safe mode と設定ソースの制御を用いて、プロジェクト / 個人の hooks、MCP、plugins、CLAUDE.md を読み込ませない。必要な挙動を CLI の help と公式資料で確認し、隔離できなければ実行しない。

Claude のファイル参照・編集・シェルなどのツールを無効化し、字幕は翻訳・説明対象のデータとして渡す。固定の実行ファイルを `spawn` の引数配列で起動し、シェル文字列として字幕を評価しない。専用の作業ディレクトリを使い、リポジトリを探索させない。プロンプトをセッション履歴に保存しない設定を使う。

Native Messaging の許可対象は、この拡張機能の正確な ID だけに限定する。入力サイズ・形式を検証し、任意コマンド / 任意パスの実行機能は作らない。生の認証出力、キー、トークンはログに記録しない。

契約の利用枠は通常の Claude / Claude Code と共用で、無制限ではない。アカウント側で追加使用の従量課金を有効にしている場合、サブスク認証でも上限後に課金される可能性がある。月額内に収めるには追加使用を無効にする必要があることを案内する。アプリだけでアカウント全体の課金設定を保証できるとは説明しない。

課金設定の根拠: https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans

## セットアップと既存環境の扱い

インストーラーは現在の Node.js / Claude Code の絶対パスを記録し、ブラウザ起動時の PATH に依存しない。CLI 更新でパスが変わった場合は再セットアップを案内する。

Brave のユーザー単位の NativeMessagingHosts にこのアプリ専用の登録ファイルを配置する。他の拡張設定・ブラウザの Preferences・既存のホスト登録は編集しない。登録する拡張 ID は設定画面から取得し、禁止された拡張管理画面や別経路の調査を行わない。

登録先の正確なファイル、内容、削除方法を実装時に示す。リポジトリ外への書き込みに実行環境の承認が必要なら、インストーラーを完成・検証してから、その具体的な操作の承認を求める。拡張のリロードや ID の共有など、手動操作が必要な部分は明確に伝える。

## 検証と完了条件

認証条件、API 非使用、設定保持、キャッシュ分離、キューの優先順位・破棄・上限、入力検証、タイムアウト・切断時の子プロセス終了、native protocol の境界を対象を絞ったテストで検証する。型チェックを実行し、最後に一度だけ拡張のビルドを行う。

実際の Claude Pro 契約のアカウントで短い疎通確認を行い、利用可能なモデルと待ち時間を確認する。その後、Brave から接続テストと短い字幕・語句解説を確認する。利用上限やブラウザ操作制約で実確認ができない場合は、未確認点を完了報告で明記する。

負荷確認のために動画全体の大量翻訳や複数 CLI の同時実行はしない。開発サーバーも起動しない。依頼された PR を作成し、マージは行わない。

## 実装者に委ねる事項

UI の細かな配置、モジュール分割、専用ホスト名、入力上限、待ち行列の具体的な上限、タイムアウト・アイドル終了時間は上記制約に沿って決める。利用者が説明なく設定する値は増やさない。
